# 🌍 Как выложить eslovari.ru на Selectel и привязать домен

Инструкция для новичков, шаг за шагом. Итог: сайт работает по адресу
`https://eslovari.ru` с бесплатным HTTPS-сертификатом, базой PostgreSQL,
ежедневными резервными копиями и закрытым сервером.

Как это устроено на сервере:

```
Интернет ──► Caddy (порты 80/443, HTTPS) ──► Django + gunicorn ──► PostgreSQL
                     └─ /media/ (аватары)
```

Всё запускается в Docker одной командой. Наружу открыты только порты 22 (SSH),
80 и 443. База и сам Django из интернета недоступны.

---

## 1. Создать сервер в Selectel

1. Зарегистрируйтесь на <https://selectel.ru> и пополните баланс.
2. **Облачная платформа → Серверы → Создать сервер.**
3. Параметры:
   - **Источник:** Ubuntu 24.04 LTS (64-bit);
   - **Конфигурация:** 1–2 vCPU, **2 ГБ RAM**, диск 20–30 ГБ (SSD).
     Для старта этого хватает; потом можно увеличить без переустановки;
   - **Сеть:** с **публичным IP-адресом** (запишите его, это `IP_СЕРВЕРА`);
   - **SSH-ключ:** добавьте свой публичный ключ (см. ниже). Вход по ключу
     безопаснее пароля.
4. Нажмите «Создать». Через минуту сервер готов.

**Как сделать SSH-ключ (Windows 10/11):** откройте PowerShell и выполните

```powershell
ssh-keygen -t ed25519
```

Нажимайте Enter на все вопросы. Содержимое файла
`C:\Users\ВАШЕ_ИМЯ\.ssh\id_ed25519.pub` вставьте в Selectel при создании сервера.

## 2. Привязать домен eslovari.ru

Домен покупается у регистратора (REG.RU, RU-CENTER и т.п.; в Selectel тоже
можно). Дальше нужно, чтобы имя указывало на IP сервера, — для этого
создаются **DNS-записи типа A**.

**Вариант А: DNS у регистратора (проще).** В панели регистратора откройте
управление DNS-зоной домена и добавьте:

| Тип | Имя (хост) | Значение | TTL |
|---|---|---|---|
| A | `@` | `IP_СЕРВЕРА` | 3600 |
| A | `www` | `IP_СЕРВЕРА` | 3600 |

**Вариант Б: DNS в Selectel.** В панели Selectel откройте раздел **DNS-хостинг**,
добавьте зону `eslovari.ru` и те же две A-записи. Затем у регистратора замените
NS-серверы домена на те, что покажет Selectel.

Записи начинают работать через 15 минут – 24 часа. Проверить:

```powershell
nslookup eslovari.ru
```

Должен вернуться `IP_СЕРВЕРА`. **Не запускайте шаг 5, пока домен не указывает
на сервер**: иначе HTTPS-сертификат не выпустится.

## 3. Первый вход и защита сервера

```bash
ssh root@IP_СЕРВЕРА
```

Обновите систему и включите автоматические обновления безопасности:

```bash
apt update && apt upgrade -y
```

```bash
apt install -y unattended-upgrades fail2ban ufw git
```

```bash
dpkg-reconfigure -plow unattended-upgrades
```

Файрвол: оставляем только SSH и веб:

```bash
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp && ufw --force enable
```

`fail2ban` после установки сам блокирует IP, которые подбирают пароль к SSH.

Запретите вход по паролю (только по ключу). **Сначала убедитесь, что вход по
ключу работает**, затем:

```bash
sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config && systemctl restart ssh
```

## 4. Установить Docker

```bash
curl -fsSL https://get.docker.com | sh
```

Проверка: `docker compose version` должна показать версию.

> Docker сам открывает проброшенные порты в обход `ufw`. В нашем
> `docker-compose.prod.yml` наружу проброшены только 80 и 443 (Caddy), поэтому
> база и Django из интернета не видны.

## 5. Загрузить сайт и запустить

```bash
git clone https://github.com/K4linin/eslovari-main.git /opt/eslovari
```

```bash
cd /opt/eslovari && python3 deploy/make_env.py --server
```

> Если репозиторий приватный, GitHub попросит логин и **токен** вместо пароля:
> создайте его в GitHub → Settings → Developer settings → Personal access tokens
> (доступ только на чтение этого репозитория).

Скрипт создаст `.env` со случайными `SECRET_KEY`, паролем базы и **секретным
адресом админки** (`ADMIN_URL=panel-xxxxxxxx`, запишите его). Откройте файл и
проверьте остальные строки:

```bash
nano .env
```

Обязательно:

```
ALLOWED_HOSTS=eslovari.ru,www.eslovari.ru
CSRF_TRUSTED_ORIGINS=https://eslovari.ru,https://www.eslovari.ru
DOMAIN=eslovari.ru
ACME_EMAIL=ваша@почта.ru
```

Сохраните (Ctrl+O, Enter, Ctrl+X) и запустите:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Первый запуск займёт 2–3 минуты. Затем загрузите демо-данные (по желанию) и
создайте администратора:

```bash
docker compose -f docker-compose.prod.yml exec web python manage.py seed_data
```

```bash
docker compose -f docker-compose.prod.yml exec web python manage.py createsuperuser
```

Откройте `https://eslovari.ru` — замок в адресной строке появится сам: Caddy
получает сертификат Let's Encrypt и продлевает его автоматически.

**Сразу после первого входа** администратором: Профиль → «Включить 2FA».
На сервере `ADMIN_REQUIRE_2FA=True`, поэтому без 2FA панель наполнения
(`https://eslovari.ru/panel-xxxxxxxx/`) не откроется.

## 6. Почта для «Забыли пароль?»

Без настройки почты письма восстановления никуда не уйдут. Проще всего
Яндекс 360 для домена (или обычный ящик Яндекса с паролем приложения).
Допишите в `.env`:

```
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.yandex.ru
EMAIL_PORT=465
EMAIL_USE_SSL=True
EMAIL_HOST_USER=noreply@eslovari.ru
EMAIL_HOST_PASSWORD=пароль-приложения
DEFAULT_FROM_EMAIL=eSlovari <noreply@eslovari.ru>
```

И перезапустите: `docker compose -f docker-compose.prod.yml up -d`.

## 7. Резервные копии

Копия базы и аватаров одной командой (сохраняются в `/opt/eslovari/backups`,
хранятся 14 дней):

```bash
cd /opt/eslovari && sh deploy/backup.sh
```

Чтобы делать копию каждую ночь в 3:30, выполните `crontab -e` и добавьте строку:

```
30 3 * * * cd /opt/eslovari && sh deploy/backup.sh >> /var/log/eslovari-backup.log 2>&1
```

Копии на том же сервере не спасут, если сломается сам сервер. Поэтому:

- в Selectel включите **резервное копирование / снапшоты диска** сервера;
- время от времени скачивайте копии к себе:
  `scp root@IP_СЕРВЕРА:/opt/eslovari/backups/db_*.sql.gz .`

Восстановление базы из копии:

```bash
gunzip -c backups/db_ДАТА.sql.gz | docker compose -f docker-compose.prod.yml exec -T db psql -U eslovari -d eslovari
```

## 8. Как обновлять сайт

```bash
cd /opt/eslovari && git pull && docker compose -f docker-compose.prod.yml up -d --build
```

Миграции базы применяются автоматически при старте.

Полезные команды:

| Что | Команда |
|---|---|
| Логи сайта | `docker compose -f docker-compose.prod.yml logs -f web` |
| Логи HTTPS/Caddy | `docker compose -f docker-compose.prod.yml logs -f caddy` |
| Перезапуск | `docker compose -f docker-compose.prod.yml restart` |
| Разблокировать вход пользователю | `docker compose -f docker-compose.prod.yml exec web python manage.py axes_reset_username ИМЯ` |
| Снять все блокировки | `docker compose -f docker-compose.prod.yml exec web python manage.py axes_reset` |

## 🛡 Безопасность: чек-лист «чтобы сайт не снесли»

Что уже встроено в код:

- HTTPS везде: HTTP перенаправляется на HTTPS, включён HSTS;
- cookie только по HTTPS (`__Host-` префикс, `HttpOnly`, `SameSite`);
- Content-Security-Policy: браузер выполняет скрипты только с нашего домена,
  это блокирует большинство XSS-атак;
- защита от CSRF, clickjacking (`X-Frame-Options: DENY`), подмены `Host`;
- пароли хэшируются Argon2, правила сложности паролей;
- блокировка после 5 неверных паролей (django-axes), лимит регистраций с IP,
  ловушка для ботов;
- 2FA для пользователей и обязательная 2FA для админки;
- секретный адрес админки, вход в неё только через общий защищённый вход;
- загрузка файлов ограничена: аватар до 2 МБ (только картинки), Excel до 5 МБ;
- Django и база работают не от root, база не видна из интернета.

Что сделать вам:

- [ ] Вход на сервер только по SSH-ключу, пароль отключён (шаг 3).
- [ ] Включены `ufw`, `fail2ban`, автообновления (шаг 3).
- [ ] `.env` никому не пересылайте и не коммитьте в git.
- [ ] Администраторы включили 2FA.
- [ ] Резервные копии делаются и **хранятся не только на сервере** (шаг 7).
- [ ] Раз в месяц: `git pull` и пересборка, чтобы получить обновления
      Django и библиотек (шаг 8).
- [ ] По желанию: поставьте сайт за DDoS-защиту (в Selectel есть услуга
      защиты от DDoS) или за CDN.

## 🧩 Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| Сайт не открывается, `ERR_CONNECTION_REFUSED` | Контейнеры не запущены: `docker compose -f docker-compose.prod.yml ps`, смотрите логи. |
| Ошибка сертификата / Caddy пишет `challenge failed` | Домен ещё не указывает на IP сервера (шаг 2) или закрыты порты 80/443 в `ufw`. |
| `Bad Request (400)` | Домена нет в `ALLOWED_HOSTS` в `.env`. |
| `CSRF verification failed` при входе | Нет домена с `https://` в `CSRF_TRUSTED_ORIGINS`. |
| Не приходят письма | Не настроены `EMAIL_*` (шаг 6) или пароль приложения неверный. |
| Сайт не стартует, в логах `SECRET_KEY не задан` | В `.env` пустой или короткий `SECRET_KEY`; перегенерируйте: `python3 -c "import secrets; print(secrets.token_urlsafe(50))"`. |
