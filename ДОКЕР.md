# 🐳 Запуск через Docker

Docker поднимает сайт вместе с базой PostgreSQL. Python и PostgreSQL на
компьютер ставить не нужно.

## Локально (для проверки и разработки)

1. Установите **Docker Desktop** (<https://www.docker.com/products/docker-desktop/>).
2. В папке проекта выполните:

```bash
docker compose up -d --build
```

3. Загрузите демо-данные и создайте администратора:

```bash
docker compose exec web python manage.py seed_data
```

```bash
docker compose exec web python manage.py createsuperuser
```

4. Откройте <http://127.0.0.1:8000/>.

Остановить: `docker compose down`. Данные базы при этом сохраняются
(в Docker-томе `pgdata`). Удалить вместе с данными: `docker compose down -v`.

> Локальный `docker-compose.yml` работает в режиме `DEBUG=True` с тестовыми
> паролями — **не используйте его на сервере**.

## На сервере

Для сервера есть отдельный файл `docker-compose.prod.yml`: он добавляет Caddy
(HTTPS-сертификат), берёт секреты из `.env` и не открывает базу наружу.
Пошагово — в **[ХОСТИНГ.md](ХОСТИНГ.md)**.

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

## Что внутри

| Файл | Зачем |
|---|---|
| `Dockerfile` | Образ сайта: Python 3.13, зависимости, собранная статика, запуск через gunicorn не от root. |
| `deploy/entrypoint.sh` | При старте применяет миграции базы. |
| `docker-compose.yml` | Локально: сайт + PostgreSQL. |
| `docker-compose.prod.yml` | Сервер: сайт + PostgreSQL + Caddy (HTTPS). |
| `deploy/Caddyfile` | Настройки Caddy: домен, редирект с www, раздача аватаров. |
| `deploy/backup.sh` | Резервная копия базы и загруженных файлов. |
| `deploy/make_env.py` | Создаёт `.env` со случайными секретами. |
